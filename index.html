01 study_assistant.py

2025

BUILT

AI Study Assistant

A chatbot that answers questions from my own lecture notes: the notes are split into chunks, embedded, and the closest ones are passed to an LLM as context. Built to understand retrieval and prompt design rather than to trust a demo.

  • Python
  • LLM APIs
  • Streamlit

architecture

Document upload

Notes are added through the Streamlit sidebar and read into the session on upload.

Text extraction

Raw text is pulled out of each file and cleaned up — whitespace, page breaks, stray headers.

Chunking

Long text is split into overlapping chunks, sized so each one carries enough context to be useful on its own.

Embeddings

Every chunk becomes a vector, so similarity becomes arithmetic rather than keyword matching.

Vector search

The question is embedded the same way and the nearest chunks are returned.

LLM

Retrieved chunks and the question are assembled into one prompt and sent to the model.

Answer

The answer is grounded in retrieved notes, so it can be checked against the source instead of trusted blindly.

Technical case study

/ problem

Asking a model about my own coursework gave confident answers that were not in my notes. The real problem was retrieval, not generation.

/ approach

Keep the model out of the storage layer: embed the notes once, retrieve per question, and pass only the relevant chunks as context.

/ challenges

Chunk size traded context against precision — chunks too small lost the surrounding argument, chunks too large buried the matching sentence in noise.

/ lessons

Retrieval quality sets the ceiling on answer quality. Prompt tweaks only help once the retrieved context is already right.

02 recommender.ipynb

2025

BUILT

Movie Recommendation System

A content-based recommender over a public film dataset — cleaning with pandas, features built from genres and keywords, and cosine similarity to find near matches. Served through a small Streamlit interface.

  • pandas
  • scikit-learn
  • Streamlit

architecture

Dataset

Public film metadata loaded into a pandas DataFrame — titles, genres, keywords, overview text.

Data cleaning

Nulls and duplicates removed, and the JSON-looking columns parsed into usable lists. This was the largest part of the work.

Feature extraction

Genres and keywords are merged into one text field per film, then vectorised — the representation decides what counts as "similar".

Similarity

Cosine similarity between film vectors. No user ratings involved — it recommends by resemblance, not by watching behaviour.

Recommendations

Top nearest titles returned through a small Streamlit view that picks a film and lists its neighbours.

Technical case study

/ problem

Recommendations should not need a ratings database. Content alone can get surprisingly far.

/ approach

Represent each film as a bag of its genres and keywords, then rank every other film by cosine similarity to it.

/ challenges

Messy nested fields and a heavily skewed long tail: obscure films with thin metadata match badly no matter the metric.

/ lessons

Feature design did most of the work. The model itself was a few lines; the cleaning was the project.

03 cnn_mnist.py

2024

BUILT

Handwritten Digit Classifier

My first real deep learning project: a convolutional network in PyTorch trained on MNIST, with training curves, a confusion matrix and a drawing canvas so I could test it on my own handwriting.

  • PyTorch
  • NumPy
  • Matplotlib

architecture

MNIST dataset

28×28 grayscale digits used for training and testing, split into train and evaluation sets.

Preprocessing

Tensors normalised to a fixed scale, and canvas drawings resized and centred so they resemble the training distribution.

CNN

Convolution and pooling layers that learn strokes and edges, followed by fully connected layers producing ten class scores.

Training

Mini-batch training over several epochs with cross-entropy loss and an optimiser, tracking loss and accuracy per epoch.

Evaluation

A confusion matrix rather than one accuracy number, to see which digits get confused with which.

Prediction

A drawing canvas feeds the model directly, so the failures are in my own handwriting rather than in a test set.

Technical case study

/ problem

Learn the mechanics of training a network, not just call a library function.

/ approach

A small CNN in PyTorch with an explicit training loop, plus a canvas interface to test it on inputs it had never seen.

/ challenges

My handwriting broke it far more often than the test set suggested, which pointed at preprocessing rather than architecture.

/ lessons

Centring and normalising the input mattered as much as the layer stack. A confusion matrix told me more than accuracy alone.

06 — Research

Research & Experiments

READING LOG

A reading log focused on making AI inference cheaper to run at the edge — three papers on hardware, instruction sets and memory movement.

Computer Architecture · Edge AI

A Lightweight Hardware Architecture for Energy-Efficient Edge AI Inference

Edge inference is bounded by energy and area rather than peak throughput. The interesting part is the design space that opens once a smaller accelerator is acceptable in exchange for less energy per inference.

notes: Efficiency is a systems property — data movement and idle power can matter more than a headline multiply-accumulate count.

Find on Scholar ↗

Computer Architecture · RISC-V

Performance and Energy Optimization of RISC-V Processors for Edge AI Applications

An open instruction set is only useful for edge AI if the extended instructions pay for themselves. This looks at where RISC-V extensions and pipeline choices can cut both runtime and energy for the same network.

notes: Relevant to the deployment gap: hardware-level optimisation is the next real step after a model leaves a notebook.

Find on Scholar ↗

Computer Architecture · Compute-in-Memory

Reducing Data Movement in Edge AI Through Compute-in-Memory Architecture

Most of the energy in inference is spent moving weights and activations, not multiplying them. Compute-in-memory attacks that directly by doing the arithmetic where the data already sits.

notes: The open question for me: how much accuracy and flexibility is traded for the energy win, and how that changes model design.

Find on Scholar ↗
